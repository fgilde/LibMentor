# Release setup

## One-time setup

Create the public `fgilde/LibMentor` repository and push `main`. Enable GitHub Pages with GitHub Actions as its source.

In the `fgilde` NuGet account, create a Trusted Publishing policy:

| Field | Value |
| --- | --- |
| Repository owner | `fgilde` |
| Repository | `LibMentor` |
| Workflow file | `release.yml` |
| Package scope | `LibMentor` |
| Environment | Leave empty |

Allow the first package publication as well as new versions. Confirm that the package ID is available before the first push; an absent GitHub repository does not reserve a NuGet ID.

## Release

1. Change the version in `Directory.Build.props` and `libmentor.json`.
2. Run the CI checks locally or through a pull request.
3. Push a matching `v<version>` tag. `v0.1.0` publishes package `LibMentor` version `0.1.0`.

The release workflow validates the tag against the project version, runs tests, packs and installs the actual package, exercises the CLI, then exchanges OIDC credentials and publishes. Do not tag again to replace a package; NuGet versions are immutable.

The normal CI workflow tests Windows and Linux, checks formatting, packs and smoke-tests the actual tool. Documentation deployment uses the CLI from the same source checkout.

## Optional Context7 registration

After the documentation URL is public, use Context7's authenticated API to add its `llms.txt` URL. The optional workflow is manually dispatched and requires repository secret `CONTEXT7_API_KEY`. It does not run for pull requests. Ownership claiming uses the public key generated by Context7's own claiming UI; never invent a key or overwrite an existing `context7.json`.
